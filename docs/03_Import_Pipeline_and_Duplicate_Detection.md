# Excel & CSV Ingestion Pipeline & Duplicate Detection Architecture

## 1. Pipeline Overview

The ingestion engine processes monthly, quarterly, semi-annual, or overlapping grievance reports generated by the call center systems.

```text
Uploaded File (.xlsx / .csv)
       │
       ▼
1. File Format & Header Scan (Auto-detects real header row across banners)
       │
       ▼
2. Column Mapping & Schema Normalization (CompId, StatusRemarks, Dates, etc.)
       │
       ▼
3. Batch Processing in Chunks of 500 records
       │
       ├─► Existing CompId Found?
       │        ├─► Field Differences (Status / Officer / Solution)?
       │        │        ├─► YES: Insert into GrievanceStatusHistory + Update Grievance
       │        │        └─► NO: Mark as Unchanged (Skip duplicate)
       │        └─► Is Old File Regressing Closed to WIP?
       │                 └─► Conflict Guard preserves Closed status
       │
       └─► New CompId?
                └─► Compute Age Bucket & Risk Flags -> Insert into Grievances
       │
       ▼
4. Commit MSSQL Transaction & Record ImportBatch Summary
       │
       ▼
5. Instant Dynamic Refresh of Dashboard KPIs and Analytics
```

## 2. Duplicate Detection Rules

1. **Uniqueness Key**: `CompId` serves as the primary business identifier.
2. **Re-Uploading Exact Files**: If the same report is uploaded again (e.g. 5,154 records), the system marks all 5,154 records as `Unchanged`, performs 0 duplicate inserts, and completes verification in ~1.0 second.
3. **Overlapping Months**: If a 6-month report contains records already uploaded in a 1-month report:
   - If an existing complaint remains in `WIP` with identical fields: Skipped as unchanged.
   - If the complaint transitioned from `WIP` to `Closed`: The grievance record is updated to `Closed` with its `CSolution` and `ResolutionDate`, and an entry is added to `GrievanceStatusHistory`.
   - Never deletes historical records simply because they are missing from an uploaded file.
